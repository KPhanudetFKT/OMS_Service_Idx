# Architecture Principles — Freshket Platform

## Go Microservice Pattern

All Go services (`oms-services-order`, `oms-services-product`, `cms-services-customer`, etc.) follow identical structure:

```
<service>/
├── cmd/
│   ├── server/main.go        # HTTP server entry point
│   ├── migrate/main.go       # DB migration runner
│   ├── job/main.go           # Kafka consumer / background job
│   └── scheduler/main.go     # Cron/scheduled tasks
├── pkg/ or service/          # Domain logic: *_service.go, *_repository.go, *_model.go
├── http/                     # HTTP layer: router, middleware, handlers
├── event/                    # Kafka producers and consumers
├── thirdparty/ or infrastructure/api/  # HTTP clients to other services
├── database/                 # GORM setup, migration files
├── config/                   # Viper config + config.yaml
└── api/                      # OpenAPI YAML specs
```

### Code Generation Rules
- OpenAPI specs in `api/*.yaml` → `make oapi-codegen` → `*.gen.go` (Echo server stubs)
- Mocks generated by Mockery → run `mockery` after changing interfaces
- **Never hand-edit** `*.gen.go` or `*_mock.go` files

### Context Propagation
- Every I/O function must accept `context.Context` as first parameter
- Extract from Echo/Fiber request context
- Use `context.WithoutCancel` for fire-and-forget goroutines (preserves trace ID)
- Never use `context.TODO()`

### Configuration
- Viper reads `.env` (local) or `config/config.yaml`
- Copy `.env.example` to `.env` to start
- Environment variable convention: YAML key → uppercase + underscores (e.g., `mysql.host` → `MYSQL_HOST`)
- Private Go modules: `export GOPRIVATE=github.com/freshket`

### Databases
- **MySQL** (primary): via GORM — business data
- **MSSQL** (legacy): SQL Server — legacy freshketdev database, read-only in most services
- Migrations: `cmd/migrate` or `cmd/migration` entry point, Go migration files in `database/migration/`

### HTTP Framework
- `oms-services-order`, `oms-services-product`, `oms-services-content`, `oms-service-payment`, `crm-customer-services`: Echo v4
- `cms-services-customer`: Fiber v2 + uber-go/fx (dependency injection)

### Linting
- All Go services: golangci-lint with `new: true` (only new issues flagged)
- Run: `make lint`
- Generated files (`*.gen.go`, `*.mock.go`) excluded

## NestJS Serverless Pattern (oms-services-nestjs)

```
oms-services-nestjs/
├── apps/
│   ├── authorizer/           # Customer JWT authorizer (API Gateway)
│   ├── authorizer-staff/     # Staff JWKS authorizer
│   ├── authorizer-internal/  # Internal API key authorizer
│   ├── promotion/            # Promotion logic
│   ├── notification/         # Notification delivery
│   ├── orderadapter/         # Order data transformation
│   ├── otp/                  # OTP service
│   └── pdpa/                 # Privacy/consent management
├── libs/
│   ├── bootstraper/          # Lambda bootstrap
│   ├── lambdakafka/          # Kafka for Lambda
│   ├── auth/                 # Auth utilities
│   ├── identity-header-middleware/
│   └── otel-logging/         # OpenTelemetry logging
└── serverless-internal.yml   # Lambda function definitions
```

- Deploy: AWS Lambda via Serverless Framework
- Dual mode: Lambda + K8s container (serverless-*-container.yml)
- Kafka: kafkajs library

## Authentication Architecture

| Token Type | Header | Validator | Used By |
|-----------|--------|-----------|---------|
| Customer JWT | `Authorization: Bearer <token>` | `authorized.go` | External customer APIs |
| Staff JWT | `Authorization: Bearer <token>` | `authorized_staff.go` (JWKS) | Admin/backoffice APIs |
| Internal | `X-API-Key` + HMAC signature | `authorized_internal.go` | Service-to-service |
| Lambda authorizer | API Gateway event | `authorizer*` apps | NestJS Lambda functions |

## Event-Driven Patterns

- Kafka broker: Confluent Cloud `pkc-l9wvm.ap-southeast-1.aws.confluent.cloud:9092`
- Topic naming: `{domain}.{entity}.{action}[.{env-suffix}]`
  - Example: `oms.order.created`, `crm.user.registered.sit`
- Go producers: Shopify/sarama (`oms-services-order`, `oms-services-product`, `oms-services-content`)
- Go consumers: segmentio/kafka-go (`oms-service-payment`, `cms-services-customer`, `crm-customer-services`)
- DLQ: Failed messages alert to Slack

## Deployment Pipeline

```
Feature Branch → PR → GitHub Actions CI → merge to develop
→ push deploy/x.x.x tag → ArgoCD syncs Helm chart → SIT
→ push release/x.x.x tag → ArgoCD syncs + Lambda deploy → UAT / PROD
```

- Go CI: `go test -v ./...` (golangci-lint)
- Frontend CI: Nx Cloud (format, lint, test, type-check)
- Secrets: `FK_JENKINS_USERNAME`, `FK_JENKINS_ACCESS`
- K8s config: `fkt-platform-charts/` — Helm charts with `configs/sit/`, `configs/uat/`, `configs/prod/`
